# AI 2024 Assignment 6 Report

## Title
Diffusion Models for Pixiv Facial Illustration Generation  
以擴散模型生成 Pixiv 臉部插畫之實作與分析

## 1. Introduction
This project implements a Denoising Diffusion Probabilistic Model (DDPM) for anime-style facial illustration generation using the `Face of Pixiv Top Daily Illustration 2020` dataset. The objective is to construct a complete diffusion-model pipeline, including data preprocessing, model design, training, evaluation, and visualization.  
本專案以 `Face of Pixiv Top Daily Illustration 2020` 資料集為基礎，實作一套用於動漫風格臉部插畫生成的去噪擴散機率模型（Denoising Diffusion Probabilistic Model, DDPM）。本作業之目標在於完成一個具備資料前處理、模型設計、訓練、評估與視覺化能力的完整擴散模型流程。

Diffusion models have recently become an important class of generative models because they are capable of producing high-quality and diverse samples through iterative denoising. In this assignment, the model is trained to learn the distribution of cropped facial illustrations and then generate new images from Gaussian noise.  
擴散模型近年已成為生成式模型的重要方法之一，其優勢在於可透過逐步去噪的方式生成高品質且具多樣性的樣本。本作業即透過學習裁切後的人臉插畫分布，使模型能自高斯隨機噪聲逐步生成新的臉部插畫影像。

## 2. Dataset Description
The dataset used in this assignment is stored in the local folder `crop_2020_img`. A local scan confirmed that this folder contains approximately `94,749` cropped face images. These images are primarily RGB illustrations with diverse drawing styles, color palettes, and levels of detail.  
本作業所使用的資料集已存放於本機資料夾 `crop_2020_img` 中。經本地掃描確認，該資料夾共包含約 `94,749` 張臉部裁切影像。這些影像主要為 RGB 插畫，且具有多樣化的繪圖風格、配色方式與細節表現。

This dataset is appropriate for diffusion-based generation for three main reasons. First, the images are face-centered, which reduces background complexity and helps the model concentrate on facial structure. Second, the dataset contains wide stylistic variation, which is beneficial for learning a rich generative distribution. Third, the overall dataset size is sufficiently large to support stable generative training.  
此資料集適合用於擴散模型生成之原因主要有三：其一，影像已聚焦於臉部區域，可有效降低背景複雜度，使模型更專注於人物五官與髮型結構；其二，資料集涵蓋多樣化畫風，有助於模型學習更豐富的生成分布；其三，整體資料量充足，足以支撐生成式模型的訓練需求。

## 3. Data Preprocessing
The preprocessing pipeline is implemented in `train_diffusion.py`. Each image is loaded from disk, converted to RGB format, resized to a fixed square resolution, transformed into a tensor, and normalized from `[0, 1]` to `[-1, 1]`.  
資料前處理流程實作於 `train_diffusion.py` 中。每張影像會先自磁碟載入，轉換為 RGB 格式，再縮放至固定方形解析度，接著轉為 tensor，最後將像素值由 `[0, 1]` 正規化至 `[-1, 1]`。

This normalization is necessary because DDPM training assumes a stable continuous representation of the image space. During training, Gaussian noise is injected into the normalized image according to the diffusion timestep.  
此正規化步驟為必要處理，因為 DDPM 訓練過程假設影像位於穩定的連續數值空間中。於訓練階段，模型會依據所抽取之 diffusion timestep，將高斯噪聲加入正規化後的影像。

## 4. Methodology

### 4.1 Diffusion Framework
The model follows the standard DDPM formulation. In the forward process, a clean image `x_0` is gradually corrupted into a noisy sample `x_t` using a predefined beta schedule. In the reverse process, the network predicts the noise component at each timestep and iteratively denoises the sample until a new image is produced.  
本研究採用標準 DDPM 架構。在前向擴散（forward diffusion）過程中，乾淨影像 `x_0` 會依照預先定義之 beta schedule 被逐步加噪，形成帶噪樣本 `x_t`。在反向過程（reverse process）中，神經網路會於每個時間步預測噪聲成分，並逐步進行去噪，最終生成新的影像。

The default diffusion hyperparameters are as follows:  
本實作預設之擴散超參數如下：

- `beta_start = 1e-4`
- `beta_end = 2e-2`
- `diffusion_steps = 300`

### 4.2 Network Architecture
The denoising backbone is a compact U-Net. The architecture includes sinusoidal timestep embedding, residual blocks with timestep conditioning, encoder downsampling blocks, bottleneck residual layers, decoder upsampling blocks, and a final convolution layer for noise prediction.  
本模型之去噪主幹為輕量化 U-Net。架構中包含正弦時間步嵌入（sinusoidal timestep embedding）、帶時間步條件資訊之殘差區塊、編碼器下採樣區塊、瓶頸殘差層、解碼器上採樣區塊，以及最終用於噪聲預測之卷積輸出層。

This architecture is suitable because U-Net preserves spatial information through skip connections while still capturing multi-scale context, which is essential for structured face generation.  
此架構之所以合適，係因 U-Net 可透過 skip connection 保留空間資訊，同時捕捉多尺度上下文特徵，對於具結構性的人臉影像生成尤為重要。

### 4.3 Training Objective
The training objective is the mean squared error between the true Gaussian noise and the model-predicted noise:  
訓練目標為真實高斯噪聲與模型預測噪聲之間的均方誤差：

`L = E[||epsilon - epsilon_theta(x_t, t)||^2]`

The optimizer used in this project is AdamW, and the implementation supports both CPU and GPU execution.  
本專案使用 AdamW 作為最佳化器，並支援 CPU 與 GPU 兩種執行模式。

## 5. Code Structure and Function Design
Although the implementation is placed in a single script, the internal design remains modular. The main program flow is controlled by `parse_args()` and `train(config)`, while dataset loading, diffusion scheduling, evaluation, and visualization are handled by dedicated functions and classes.  
雖然本專案將主要實作集中於單一腳本中，但其內部設計仍維持模組化。整體程式流程由 `parse_args()` 與 `train(config)` 負責控制，而資料載入、diffusion schedule、評估與視覺化則由獨立函式與類別處理。

Important functions are summarized below.  
程式中較重要之函式說明如下。

### `set_seed(seed)`
Controls random seeds for Python, NumPy, and PyTorch to improve reproducibility.  
控制 Python、NumPy 與 PyTorch 之亂數種子，以提升實驗可重現性。

### `PixivFacesDataset`
Loads image files, converts them to RGB, resizes them, and applies normalization.  
負責載入影像、轉換 RGB、調整尺寸與進行正規化。

### `sinusoidal_time_embedding(timesteps, dim)`
Encodes discrete diffusion timesteps into continuous vectors so that the network can distinguish different denoising stages.  
將離散的 diffusion timestep 編碼為連續向量，使模型能辨識不同的去噪階段。

### `SimpleUNet`
Acts as the noise-prediction network. It receives a noisy image and timestep embedding, then outputs the estimated noise map.  
作為噪聲預測網路。其輸入為帶噪影像與時間步嵌入，輸出則為對應的噪聲估計結果。

### `DiffusionSchedule.q_sample(...)`
Implements the forward diffusion equation used to generate noisy training samples.  
實作前向擴散公式，用以產生訓練所需之帶噪樣本。

### `DiffusionSchedule.p_sample(...)`
Implements one reverse denoising step during sampling.  
實作生成過程中的單一步反向去噪運算。

### `DiffusionSchedule.sample(...)`
Executes the complete reverse diffusion chain to synthesize images from Gaussian noise.  
執行完整的反向擴散鏈，將高斯噪聲逐步轉換為生成影像。

### `evaluate_validation_loss(...)`
Computes average validation loss after each epoch.  
在每個 epoch 結束後計算平均驗證損失。

### `save_loss_curve(...)`, `save_sample_grid(...)`, `save_trajectory_grid(...)`
Generate figures for training curves, generated samples, and denoising trajectories.  
產生訓練曲線、生成樣本與去噪軌跡之圖表。

### `compute_style_metrics(...)`
Computes descriptive statistics such as RGB mean, RGB standard deviation, saturation, and texture intensity to compare dataset and generated samples.  
計算 RGB 平均值、RGB 標準差、飽和度與紋理強度等描述性統計量，用以比較資料集樣本與生成樣本。

## 6. Experimental Settings
The project contains three levels of experiments.  
本專案共進行三個層次之實驗。

### 6.1 Smoke Test
The smoke test uses a very small subset and only one epoch to verify that the entire pipeline can run correctly.  
Smoke test 使用極小型資料子集與單一 epoch，目的在於驗證整體訓練流程是否能正常執行。

This configuration is suitable for debugging and functional validation, but it is not sufficient for evaluating final model quality.  
此設定適合用於除錯與功能驗證，但不足以評估模型最終品質。

### 6.2 Mid-Range Comparison Experiment
To compare the learning process more meaningfully, a fixed subset of `1024` images was used for a `100`-epoch experiment on GPU, and the results at epochs `5`, `10`, `50`, and `100` were extracted from the same training run.  
為了更有意義地比較模型學習進展，本研究另外使用固定 `1024` 張影像子集與 GPU 進行 `100` 個 epoch 的訓練，並自同一條訓練曲線中擷取 `5`、`10`、`50` 與 `100` 個 epoch 的結果。

This design ensures that all milestone observations are directly comparable because they come from the same optimization trajectory.  
此設計可確保所有里程碑觀察點均來自同一條優化路徑，因此具有直接可比性。

### 6.3 Long-Horizon Compact Experiment
To analyze long-horizon optimization behavior, a compact configuration was used so that `1000` epochs could be completed within reasonable time on the local GPU. The long-horizon setting used `256` images, `64 x 64` resolution, batch size `32`, and `base_channels = 32`.  
為分析長週期訓練行為，本研究採用 compact configuration，使 `1000` 個 epoch 能於本機 GPU 上在合理時間內完成。此長週期設定使用 `256` 張影像、`64 x 64` 解析度、batch size `32`，以及 `base_channels = 32`。

The purpose of this experiment is not to claim the strongest final model, but rather to observe how validation performance changes as training continues for a long duration.  
本實驗之目的不在於宣稱其為最強最終模型，而在於觀察模型於長時間訓練下之驗證表現變化。


## 7. Results and Analysis
### 7.1 Smoke Test Result
The smoke test was executed with the following command:  
Smoke test 使用下列指令執行：

```powershell
python train_diffusion.py --max-images 32 --epochs 1 --batch-size 4 --image-size 32 --base-channels 16 --diffusion-steps 20 --sample-count 4 --keep-trajectory-steps 4 --output-dir outputs_smoke --device cuda
```

Observed results were as follows:  
實測結果如下：

- Device: CUDA
- GPU: `NVIDIA GeForce RTX 2060`
- Train loss: `1.0482`
- Validation loss: `1.0153`

This result confirms that the DDPM pipeline, GPU execution, visualization export, and checkpoint logic all function correctly. However, because only one epoch was used, this result should be interpreted solely as pipeline validation rather than final model performance.  
此結果證實 DDPM 訓練流程、GPU 執行、視覺化輸出與 checkpoint 機制皆能正常運作。然而，由於僅訓練一個 epoch，因此本結果僅能視為流程驗證，而不宜作為最終模型性能之評估依據。

### 7.2 Mid-Range Epoch Comparison
The `1024`-image comparison experiment used the following command:  
`1024` 張影像之中期比較實驗使用下列指令：

```powershell
python train_diffusion.py --max-images 1024 --epochs 100 --batch-size 32 --image-size 64 --base-channels 64 --diffusion-steps 300 --sample-count 4 --keep-trajectory-steps 4 --output-dir outputs_compare_100 --device cuda
```

The selected epoch results are shown below.  
其關鍵 epoch 結果如下表所示。

| Epoch | Train Loss | Validation Loss |
|---|---:|---:|
| 5 | 0.107784 | 0.107768 |
| 10 | 0.077464 | 0.105450 |
| 50 | 0.060583 | 0.061650 |
| 100 | 0.049681 | 0.051967 |

The best validation loss of the entire 100-epoch run was achieved at epoch `87`, with a value of `0.035226`.  
整個 100-epoch 訓練中，最佳驗證損失出現在第 `87` 個 epoch，其數值為 `0.035226`。

From these results, several observations may be made. First, the model improves substantially from epoch `5` to epoch `50`, indicating effective early-to-middle-stage learning. Second, the validation loss at epoch `10` is slightly worse than at epoch `5`, suggesting that short-term validation fluctuations are normal during stochastic optimization. Third, by epoch `100`, the model has clearly surpassed the early-stage results, confirming that multi-epoch training is necessary for meaningful visual generation.  
由上述結果可得數點觀察。首先，模型自 epoch `5` 至 epoch `50` 之間有明顯進步，顯示前中期學習效果良好。其次，epoch `10` 的驗證損失略高於 epoch `5`，說明在隨機最佳化過程中，短期驗證波動屬正常現象。最後，當訓練達到 epoch `100` 時，模型表現已顯著優於初期結果，證實多個 epoch 的訓練對有意義之影像生成而言為必要條件。

### 7.3 Long-Horizon Compact Experiment
The long-horizon compact experiment was executed using the following command:  
長週期 compact 實驗使用下列指令：

```powershell
python train_diffusion.py --max-images 256 --epochs 1000 --batch-size 32 --image-size 64 --base-channels 32 --diffusion-steps 300 --sample-count 4 --keep-trajectory-steps 4 --output-dir outputs_compare_1000 --device cuda --save-epochs 1,10,50,100,200,300,500,1000
```

The milestone results are as follows.  
其里程碑結果如下。

| Epoch | Train Loss | Validation Loss |
|---|---:|---:|
| 1 | 0.943745 | 0.785503 |
| 10 | 0.206755 | 0.208908 |
| 50 | 0.107604 | 0.102189 |
| 100 | 0.074219 | 0.085834 |
| 200 | 0.069391 | 0.061238 |
| 300 | 0.057749 | 0.112068 |
| 500 | 0.045212 | 0.166934 |
| 1000 | 0.036556 | 0.115943 |

The best validation checkpoint occurred at epoch `547`, where the validation loss reached `0.023246`.  
最佳驗證 checkpoint 出現在 epoch `547`，其 validation loss 為 `0.023246`。

This experiment reveals several academically relevant phenomena.  
此實驗呈現出數個具有分析價值之現象。

First, the model improves rapidly during the early stage, as shown by the large reduction in both training and validation loss between epochs `1` and `50`.  
第一，模型在前期學習階段進步快速，自 epoch `1` 至 epoch `50` 之間，訓練與驗證損失均大幅下降。

Second, validation performance does not decrease monotonically. For example, epoch `29` is marked as an early rebound point because validation loss temporarily rises again after a previous decline. This behavior indicates that the model has not yet stabilized during the early optimization stage.  
第二，驗證表現並非單調下降。例如，epoch `29` 被標示為 early rebound point，因為其 validation loss 在先前下降後又出現短暫回升。此現象顯示模型於早期最佳化階段尚未完全穩定。

Third, the best validation performance is not located at the final epoch. Instead, it appears at epoch `547`, indicating that the model reaches an optimal generalization state before the end of training.  
第三，最佳驗證表現並未出現在最終 epoch，而是發生於 epoch `547`。此結果意味著模型於訓練後期的某一時刻到達了最佳泛化狀態，而非持續訓練越久越好。

Fourth, epoch `500` is marked as a late rebound point. Although training loss is already low (`0.045212`), validation loss rises to `0.166934`, yielding a large train-validation gap. This suggests that prolonged training on a small subset may continue to reduce training error while harming generalization stability.  
第四，epoch `500` 被標示為 late rebound point。儘管此時 training loss 已相當低（`0.045212`），validation loss 卻上升至 `0.166934`，形成顯著的 train-validation gap。此結果顯示，若在較小的資料子集上長時間訓練，模型雖可能持續降低訓練誤差，但其泛化穩定性反而可能惡化。

Finally, epoch `1000` still does not outperform the best checkpoint. This clearly shows that "more training" does not necessarily imply "better generalization."  
最後，即使訓練持續到 epoch `1000`，其驗證表現仍未超越最佳 checkpoint。此結果清楚說明：「訓練更久」並不必然等同於「泛化更好」。

## 9. Discussion
The experimental results demonstrate that the implemented DDPM pipeline is functionally correct and capable of learning useful image structure from the Pixiv face dataset. Even under compact settings, the model shows clear convergence trends and produces progressively improved samples as training proceeds.  
本研究之實驗結果顯示，所實作之 DDPM 流程在功能上正確，並具備自 Pixiv 臉部資料集學習有用影像結構之能力。即使在 compact setting 下，模型仍可呈現明顯收斂趨勢，且生成樣本會隨著訓練進行而逐步改善。

At the same time, the long-horizon experiment shows that validation behavior can fluctuate significantly, and that the best checkpoint may occur well before the final epoch. This is an important observation for diffusion-model training, because it emphasizes the need for checkpoint selection based on validation performance rather than training duration alone.  
然而，長週期實驗同時顯示驗證表現可能出現明顯波動，且最佳 checkpoint 未必出現在最終 epoch。這一點對擴散模型訓練具有重要意義，因為它說明模型選擇應以驗證表現為依據，而非僅以訓練時間長短作為判準。

Therefore, for practical training, it is advisable to monitor validation loss continuously and preserve checkpoints at important milestones.  
因此，在實務訓練上，應持續監控 validation loss，並保存關鍵里程碑之 checkpoint，以利後續比較與最佳模型選擇。
